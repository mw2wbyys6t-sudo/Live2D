> 🔖 **修订说明**：产权所有者于 2026-07-30 当日决定降低协议限制程度，把现行协议由 CC BY-NC 4.0 国际版**降级为更严格的 CC BY-NC 2.0 Generic 通用版**（"降低" = 对被许可方的约束加严、可活动空间缩小）。CC 协议是版权所有者给被许可方的授权，**版权所有者（Licensor）不受协议 NC 条款限制**，因此降级完全合法。已按 Rev.1 (4.0) 发布的历史版本对接收者永久有效，不受本修订追溯。

## 1. 决策问题（Decision Question — Rev.2 修订版）

面向开源发布与二创生态，本项目应采用何种开源协议，才能同时满足：

1. **保留原作者产权** — 源代码、算法、角色形象、视觉资产等全部原始成果的知识产权不被剥夺；
2. **允许他人非商业性创作/二创** — 个人、社团、教育场景可自由修改、分发、衍生；
3. **防止商业盗用** — 他人不得将本项目及衍生作品包装为付费产品/SaaS/付费模型商城/企业生产工具；
4. **（Rev.2 新增）加严约束** — 防止二创作者将衍生作品切换至更宽松的 3.0/4.0 协议从而变相商用；强制二创注明**具体修改内容与日期**；要求**每一份再分发副本都带 License 全文/URI**；禁止施加 DRM 或额外技术限制。

## 3. 备选方案对比（Alternatives Considered，≥2 条被拒）

| 方案 | 优点 | 缺点 / 被拒原因 |
|------|------|----------------|
| **A · MIT**（v9.0 时使用） | 宽松、生态友好 | ❌ 无法阻止商用盗用（F3 不满足），原作者产权可被抹去（F1 不满足）；已被替换。 |
| **B · GPL v3** | 强 Copyleft，衍生必须开源 | ❌ 对"二创作品（角色形象/模型包）"是否属于衍生作品界定模糊；强制 Copyleft 会劝退普通创作者（F2 受损）；对代码层面的传染性与 CC 协议的作品层授权不可混用。 |
| **C · Apache 2.0** | 含专利授权条款 | ❌ 同样允许商用（F3 不满足）；专利条款对本项目 AI 管线的实际保护力度弱于 CC-BY-NC 的"商用即侵权"清晰边界。 |

| **✅ E · CC BY-NC 4.0（国际版）** | ① 署名（BY）强制保留产权 → F1 ✅；② 非商业（NC）显式禁止商用 → F3 ✅；③ 允许修改、衍生、分发 → F2 ✅；④ 国际通用、30+ 语言、法院判例成熟 → F4 ✅；⑤ 与软件代码（源代码）、艺术作品（角色/模型/视觉资产）均天然兼容。 | 对 NC 边界（如"接定制 Live2D 订单是否算商用"）有一定灰色地带，需在 README 中举例列明。 |

## 4. 决策（Decision）

**采用 CC BY-NC 4.0（知识共享 署名-非商业性使用 4.0 国际）作为本项目唯一许可协议。**

协议同时覆盖：源代码、配置文件、文档、AI 管线设计、角色形象生成算法、视觉资产、Live2D 绑定模板等全部项目产出。

## 5. 后果（Consequences）

### 正面 ✅
- 商用路径被**显式且合法地**切断（F3）。
- 二创/教学/社区场景完全保留，不会像 GPL 那样吓跑用户（F2）。
- 署名条款是"硬约束"，GitHub fork、二次分发、打包为桌面 App 时都必须保留 Live2D Master Agent Team 署名（F1）。
- 与 `docs/CODE_STANDARD.md` 中的贡献流程一致，外部 PR 天然署名归项目所有（合并即同意协议）。

### 负面 / 缓解 ⚠️
- **NC 灰色地带**：如"用户用本项目生成的 Live2D 角色去接稿约稿/直播带货收益"，严格说不属于"对本作品本身的商业使用"，属于使用者对**自己生成的衍生形象**的处置。已在 README 许可证章节用"（包括但不限于付费下载、广告变现、售卖 Live2D 模型、付费 SaaS 服务、企业内部商业生产等）"举例限定，只覆盖"对本项目代码/管线的直接商用包装"。
- **无法收取许可费**：商用被禁止后，项目商业化只能靠"商用授权例外（Dual License）"——保留团队另行向付费客户发放商用 License 的权利（这是 CC BY-NC 天然允许的，版权所有者不受 NC 约束）。
- **企业贡献门槛略升**：大厂员工贡献需先过内部法务确认 NC 无冲突 → 缓解：README 提供联系通道。

# 📌 Revision 2 — 2026-07-30 修订：CC BY-NC 4.0 → **CC BY-NC 2.0 Generic**（降级，加严约束）

> 本节为 Rev.2 单独决策记录。Rev.1 原 4.0 的上下文、备选、后果等仍保留于上半部分，仅用于记录决策沿革，不构成现行约束。

## R2-1. 修订决策问题

原 CC BY-NC 4.0 国际版存在的宽松点，与产权所有者的真实诉求存在偏差：

1. 4.0 允许衍生作品"兼容至 BY-SA 4.0 / GPL 等"，给变相降级留了空间；
2. 4.0 "注明更改"只要求"说明做了更改"，不要求写清具体改了什么；
3. 4.0 "标注许可"只要求提供链接，不要求每一份副本都**附带协议 URI / 文本**；
4. 4.0 对"商业使用"的判定对「企业内部使用」「间接获益」的定义较模糊。

产权所有者决定**加严**（即"降到" 2.0 版本，约束更多、被许可方活动空间更小）。

## R2-2. 修订推动力（新增 Forces Rev.2）

| 推动力 | 说明 |
|--------|------|
| F5 · 衍生协议升级担忧 | 担心二创作者把作品协议升级到 4.0，再通过 4.0 的兼容条款切到更宽松甚至商业可授权的条款，绕开 BY-NC。2.0 不兼容 3.0/4.0 的升级路径，强制衍生保持 2.0。 |
| F6 · 修改注明粒度不足 | 4.0 "You must indicate if you modified the material" 太宽松，二创者常写"已修改"但不写改什么，导致原作者声誉无法追溯。2.0 明确要求注明具体更改与日期。 |
| F7 · 副本分发许可文本丢失 | 4.0 允许只放链接，一旦链接失效或发布平台移除链接，用户就看不到协议。2.0 要求每一份副本带 URI 或全文。 |
| F8 · 商用判定更严格 | 业主希望把"企业内部生产用"和"间接广告获益"也明确纳入禁止范围。2.0 法条原文更严。 |

## R2-3. 修订备选对比

| 方案 | 描述 | 结论 |
|------|------|------|
| A · 保持 4.0 + 加一段 README 警告 | 法律效力弱，警告不能修改 CC 协议原文 | ❌ 不推荐，自制附加条款不可执行 |
| B · 切到 CC BY-NC-ND 4.0（禁止衍生） | 过于严格，与"允许二创"诉求矛盾 | ❌ 违反 F2（二创场景） |
| C · **CC BY-NC 2.0 Generic（当前修订）** | 2.0 法条更严格、强制副本带 URI、强制具体注明修改、强制衍生保持 2.0（不可升级 3.0/4.0）、商用判定范围更广，同时保留"修改/二创"权利 | ✅ 选定 |
| D · 自制"加严 BY-NC"协议 | 自制协议不具备国际法律认可，开源平台不识别 | ❌ 红线，禁止 |

## R2-4. 修订决策

**现行主分支协议 = CC BY-NC 2.0 Generic（通用版）。**

Rev.1 已发布的历史版本（commit `418e071` 之前）仍按 CC BY-NC 4.0 永久生效（版权所有者**不得撤销已发放的许可**）；自 commit `9b6c4a1` 之后，所有新提交和新发布产物按 **2.0** 发布。

## R2-5. 修订后果

### 正面（Rev.2 比 Rev.1 更符合产权所有者诉求）
- 2.0 **衍生不可升级**：二创作者无法靠升级到 4.0 / 3.0 来绕过严格约束（F5 命中）。
- 2.0 **修改注明更细**：每一次修改都要求写"改了什么 + 日期 + 原作者说明声明"（F6 命中）。
- 2.0 **每份副本都带 URI**：桌宠打包、模型导出、镜像发布**必须**内嵌 LICENSE 文本 + URI，协议不可丢失（F7 命中）。
- 2.0 **商用范围更广**：企业内部生产使用、广告间接获益都被明确禁止（F8 命中）。
- 2.0 法条出台更早（2004 年发布，2007 修正），在各国法院判例更成熟。

### 负面 / 缓解
- **兼容性**：2.0 无法与 4.0 项目互相混并（CC 版本协议不可混除非特殊情况）。缓解：本项目以"本项目自产内容为主"，极少合并外部 4.0 代码；若未来需要，则把 4.0 内容放独立目录并配单独 LICENSE（即 `dual-license/` 目录）。
- **贡献门槛略升**：对有开源经验的开发者来说，2.0 可能比 4.0 少见。缓解：README 顶部详细解读 2.0 和 4.0 的关键差异。
- **中国本地化翻译**：2.0 中文 deed 是 2004 年翻译，部分措辞偏旧。缓解：README 在"完整法律文本"下同时提供英文版 legal code 原文（效力优先）。
